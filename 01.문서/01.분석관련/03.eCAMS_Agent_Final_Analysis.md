## 📊 Executive Summary (A)

### Agent의 역할 (5줄)
1. **Socket 서버**: 포트 29895(기본)에서 대기, 클라이언트 연결마다 Fork하여 처리
2. **파일 송수신**: 3-way handshake(First/Middle/Last Chain)로 대용량 파일 분할 전송
3. **TAR 압축 처리**: 'Z' 모드(압축 해제), 'X' 모드(압축+인덱스) 자동 처리
4. **원격 명령 실행**: AES 암호화된 명령어 수신 → 복호화 → system() 실행
5. **파일 정보 조회**: 파일 크기, 권한, 소유자, 수정일시 등 메타데이터 제공

### 핵심 컴포넌트 (5개)

| 컴포넌트 | 역할 | 주요 함수 | 위험도 |
|---------|------|----------|--------|
| **ecams_svr.c** | 메인 서버, 요청 라우팅 | main(), HandleMainProc() | 🔴 High |
| **lanapi.c** | Socket I/O | Rcv_Data_Sock(), SendDataToSock() | 🟡 Medium |
| **tarsrc/** | TAR 압축/해제 | tarFileMake_ext_Z(), tarFileMake_comp_X() | 🟢 Low |
| **aessrc/** | AES-128 CBC 암호화 | aes_128_cbc_decrypt() | 🔴 **CRITICAL** |
| **md5src/** | MD5 체크섬 (추정) | (실제 사용 여부 불명) | 🟢 Low |

### TOP 3 운영 리스크

#### 1. **🔴 AES 암호화 키 하드코딩 (CRITICAL)**
```c
// ecams_svr.c:630-633
u8 szKey[16] = { 0x06, 0xa9, 0x21, 0x40, 0x36, 0xb8, 0xa1, 0x5b,
                 0x51, 0x2e, 0x03, 0xd5, 0x34, 0x12, 0x00, 0x06 };
u8 szIV[16]  = { 0x3d, 0xaf, 0xba, 0x42, 0x9d, 0x9e, 0xb4, 0x30,
                 0xb4, 0x22, 0xda, 0x80, 0x2c, 0x9f, 0xac, 0x41 };
```
- **영향**: 소스코드 유출 시 모든 암호화 통신 해독 가능
- **위험**: 원격 명령 실행 권한 탈취
- **대응**: 즉시 외부 키 관리 시스템으로 전환 필요

#### 2. **🔴 system() 직접 실행 (Remote Code Execution)**
```c
// ecams_svr.c:680, 733
retval = system(decbuf);  // 복호화된 명령어 직접 실행
```
- **영향**: 임의의 쉘 명령 실행 가능 (root 권한 시 더욱 위험)
- **위험**: 서버 장악, 데이터 유출, 랜섬웨어 등
- **대응**: 화이트리스트 기반 명령어 검증 필요

#### 3. **🟡 Fork 폭탄 + 좀비 프로세스**
```c
// ecams_svr.c:465-467
if ((forkpid = fork()) < 0) {
    continue;  // 에러 처리 없음
}
// ecams_svr.c:261
signal(SIGCHLD, SIG_IGN);  // 좀비 프로세스 방치
```
- **영향**: 프로세스 테이블 고갈, 시스템 전체 마비
- **위험**: DoS 공격, 신규 연결 거부
- **대응**: 최대 프로세스 수 제한, SIGCHLD 핸들러 수정

int ProcSystemCmd(Sock, RdBuf, RdLng)
{
    // 1. AES 키 (하드코딩!)
    u8 szKey[16] = { 0x06, 0xa9, ... };
    u8 szIV[16]  = { 0x3d, 0xaf, ... };
    
    // 2. 명령어 추출
    memcpy(tmpbuf, &RdBuf[hdlng], pulng);
    
    // 3. AES 복호화
    aes_128_cbc_decrypt(szKey, szIV, decbuf, ncount);
    
    // 4. 명령 실행 (위험!)
    retval = system(decbuf) / 256;
    
    // 5. 결과 반환
    if (!retval)
        WorkResultSendData(Sock, tmpbuf, dfCmd_DAOK);
    else
        WorkResultSendData(Sock, tmpbuf, dfCmd_EROR);
}
```

int ProcFileRcv(Sock, RdBuf, RdLng)
{
    switch (uhead->CF) {
        case dfFirstChain:
            // 파일명 추출
            sprintf(filename, "%s", &RdBuf[hdlng+dfRemoteOffset]);
            
            // 디렉토리 없으면 생성
            if (access(strDir, F_OK) != 0) {
                Local_Dir_Make(strDir);  // mkdir 재귀 호출
            }
            
            // 파일 생성
            gRcvFd = open(filename, O_RDWR|O_CREAT|O_TRUNC, 0666);
            break;
            
        case dfMiddleChain:
            // 파일 끝에 추가
            lseek(gRcvFd, 0L, SEEK_END);
            write(gRcvFd, &RdBuf[hdlng], pulng);
            break;
            
        case dfLastChain:
            // 마지막 데이터 쓰고 닫기
            if (pulng > 0) {
                lseek(gRcvFd, 0L, SEEK_END);
                write(gRcvFd, &RdBuf[hdlng], pulng);
            }
            close(gRcvFd);
            
            // TAR 처리
            if (gProcWork == 'Z')
                tarFileMake_ext_Z(tarFilename);  // 압축 해제
            if (gProcWork == 'X')
                tarFileMake_comp_X(idxFilename); // 압축 생성
            break;
    }
}
```

    gFileSize = f_st.st_size;

    loc = localtime(&f_st.st_mtime);

## 📊 요약

### ✅ 확인된 사실
1. **멀티프로세스**: 클라이언트마다 fork()
2. **3-way 전송**: First/Middle/Last Chain
3. **4가지 파일 모드**: F(수신), G(송신), Z(TAR해제), X(TAR압축)
4. **AES 암호화**: 하드코딩된 키로 명령어 암호화
5. **system() 실행**: 복호화된 명령 직접 실행

### 🔴 Critical 보안 문제
1. **AES 키 하드코딩**: 소스 유출 = 전체 시스템 장악
2. **무제한 RCE**: system() 직접 호출
3. **경로 검증 부재**: 디렉토리 순회 공격 가능

### 🟡 High 운영 문제
1. **Fork 폭탄**: 프로세스 수 제한 없음
2. **좀비 프로세스**: SIGCHLD 무시
3. **타임아웃 없음**: 네트워크 hang 가능

### 📋 즉시 조치 사항
1. AES 키 외부화 (환경변수 또는 파일)
2. 최대 프로세스 수 100으로 제한
3. Socket 타임아웃 5분 설정
4. SIGCHLD 핸들러 수정 (wait() 호출)
5. 경로 검증 로직 추가
