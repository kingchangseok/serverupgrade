# 소스 코드 분석 보고서 (server_1 vs server_2)

`server_1`(수정됨)과 `server_2`(원본/중간단계)의 소스 코드를 분석한 결과, glibc 오류 및 시스템 호출 행(hang) 현상과 관련하여 다음과 같은 사항을 확인했습니다.

## 1. 변경 사항 요약
이번 수정의 주요 목적은 파일 전송 중 발생하는 **glibc malloc assertion failure**와 **시스템 호출 행**(`getpwuid`, `getgrgid` 등) 문제를 해결하는 것입니다.

### 주요 수정 내용:
- **시스템 호출 우회**: [output.c](file:///d:/ai/antigravity/server_1/tarsrc/output.c)와 [decode.c](file:///d:/ai/antigravity/server_2/tarsrc/decode.c)에서 NSS(Name Service Switch)를 사용하는 `getpwuid`, `getgrgid`, `getpwnam`, `getgrnam` 기능을 제거했습니다. 대신 `/etc/passwd`와 `/etc/group` 파일을 직접 읽도록 수정되었습니다.
- **Malloc 체크 설정 변경**: [ecams_svr.c](file:///d:/ai/antigravity/server_1/svrsrc/ecams_svr.c)에서 환경 변수 `MALLOCK_CHECK_`(오타로 추정, 원래 `MALLOC_CHECK_`)의 값을 `3`(오류 시 중단)에서 `0`(체크 비활성화)으로 변경했습니다.
- **디버깅 코드 정리**: 다수의 `printf` 디버깅 문을 주석 처리하거나 `#ifdef DEBUG`로 감싸서 정리했습니다.

## 2. 상세 분석 결과

### A. [output.c](file:///d:/ai/antigravity/server_1/tarsrc/output.c)의 우회 로직
엔지니어는 `getpwuid`와 `getgrgid`가 내부적으로 힙(Heap) 메모리 상태에 민감하게 반응하여 행(hang)을 유발한다는 점을 정확히 짚어냈습니다.
- **해결됨**: `server_1`에서는 이러한 호출을 주석 처리하고 직접 파일을 읽는 헬퍼 함수를 사용하여 문제를 해결했습니다.
- **비교**: `server_2`에도 구현은 되어 있었으나, 여전히 원본 `getgrgid`를 호출하는 부분이 남아 있어 문제가 지속될 수 있는 상태였습니다.

### B. 새로 도입된 버그 ([decode.c](file:///d:/ai/antigravity/server_2/tarsrc/decode.c))
우회 로직을 추가하는 과정에서 프로그램의 비정상 종료를 유발할 수 있는 두 가지 치명적인 버그가 발견되었습니다.

1.  **초기화되지 않은 포인터 접근 (치명적)**:
    [th_get_gid](file:///d:/ai/antigravity/server_2/tarsrc/decode.c#141-168) ([decode.c:156](file:///d:/ai/antigravity/server_1/tarsrc/decode.c#L156)):
    ```c
    final_gid = get_gid_from_file(t->th_buf.gname);
    if(final_gid != (gid_t) -1) {
        return gr->gr_gid; // 버그: 'gr' 변수가 NULL이거나 초기화되지 않은 상태에서 접근!
    }
    ```
    그룹 정보를 파일에서 찾았을 경우, 초기화되지 않은 [gr](file:///d:/ai/antigravity/server_2/tarsrc/output.c#96-131) 변수를 참조하여 **세그멘테이션 오류(Segfault)**가 발생할 확률이 매우 높습니다. `return final_gid;`로 수정해야 합니다.

2.  **잘못된 변수 사용**:
    [th_get_uid](file:///d:/ai/antigravity/server_1/tarsrc/decode.c#82-102) ([decode.c:92](file:///d:/ai/antigravity/server_1/tarsrc/decode.c#L92)):
    ```c
    uid = get_uid_from_file(t->th_buf.gname); // 버그: 사용자를 조회할 때 그룹명(gname)을 사용함!
    ```
    사용자 명칭인 `t->th_buf.uname`을 전달해야 합니다.

### C. Malloc 오류 처리 ([ecams_svr.c](file:///d:/ai/antigravity/server_1/svrsrc/ecams_svr.c))
`MALLOCK_CHECK_` 설정을 `0`으로 변경한 것은 메모리 오염(Corruption)이 발생하고 있음을 반증합니다.
- **참고**: 이 설정은 "Fatal glibc error"를 일시적으로 보이지 않게 할 뿐, **근본적인 메모리 오염 문제를 해결한 것이 아닙니다**. 프로그램이 불안정한 상태로 계속 실행되도록 방치하는 것일 수 있습니다.

### D. `encode.c`의 불완전한 우회 (주의)
시스템 호출 우회 작업이 **완벽하지 않습니다**. [output.c](file:///d:/ai/antigravity/server_1/tarsrc/output.c)와 [decode.c](file:///d:/ai/antigravity/server_2/tarsrc/decode.c)는 수정되었으나, `encode.c`에는 여전히 문제가 되는 호출이 남아 있습니다:
- `th_set_user` ([encode.c:160](file:///d:/ai/antigravity/server_1/tarsrc/encode.c#L160))
- `th_set_group` ([encode.c:177](file:///d:/ai/antigravity/server_1/tarsrc/encode.c#L177))

에이전트가 서버에서 파일을 수집하여 tar로 묶는 과정(생성 프로세스)을 수행할 때 동일한 행(hang)이나 크래시가 발생할 수 있습니다.

## 3. 결론 및 권장 조치
`server_1`의 변경 사항은 보고된 시스템 호출 행 문제를 어느 정도 해결하지만, 불완전하고 새로운 오류를 포함하고 있습니다.

### 권장 조치 사항:
1.  **[decode.c](file:///d:/ai/antigravity/server_2/tarsrc/decode.c)의 치명적 버그 수정**:
    - **[th_get_gid](file:///d:/ai/antigravity/server_2/tarsrc/decode.c#141-168)**: `return gr->gr_gid;`를 `return final_gid;`로 변경하여 세그멘테이션 오류 방지.
    - **[th_get_uid](file:///d:/ai/antigravity/server_1/tarsrc/decode.c#82-102)**: `t->th_buf.gname`을 `t->th_buf.uname`으로 변경하여 정상적인 UID 조회 보장.
2.  **우회 로직 완성**: 파일 생성이 필요한 경우 `encode.c`에도 동일한 우회 로직을 적용해야 합니다.
3.  **환경 변수 이름 수정**: `MALLOCK_CHECK_`를 `MALLOC_CHECK_`(K 제외)로 수정해야 glibc의 제어 기능이 정상 작동합니다. (단, 0으로 설정 시 오류는 계속 숨겨지게 됩니다.)
4.  **근본적인 원인 파악**: 메모리 오염의 근본 원인(버퍼 오버플로우 등)을 찾기 위해 Valgrind 등의 도구를 사용한 정밀 진단을 권장합니다.
