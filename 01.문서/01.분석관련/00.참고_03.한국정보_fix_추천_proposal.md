# [문서 2] Antigravity 추천 수정 가이드 (Fatal glibc error 대응)

`Fatal glibc error`는 프로그램 어딘가에서 정해진 메모리 범위를 넘어서 썼을 때(Buffer Overflow) 발생합니다. 이를 안정적으로 해결하기 위한 Antigravity의 권장 수정안입니다.

## 1. 시스템 함수 우회 코드의 정상화 (Bug Fix)
엔지니어가 추가한 우회 로직 중 치명적인 오류(오동작 및 크래시 위험)가 있는 부분을 바로잡아야 합니다.

### 수정 전 (엔지니어의 불안정한 상태)
```c
/* decode.c - th_get_gid 함수 */
final_gid = get_gid_from_file(t->th_buf.gname);
if(final_gid != (gid_t) -1) {
    return gr->gr_gid; // BUG: gr은 NULL이므로 여기서 프로그램 종료됨
}
```

### 추천 수정 후 (Antigravity 제안)
```c
/* decode.c - th_get_gid 함수 */
final_gid = get_gid_from_file(t->th_buf.gname);
if(final_gid != (gid_t) -1) {
    return final_gid; // 정상적으로 찾은 ID를 반환
}
```

---

## 2. 완전한 우회 적용 (Missing Fix)
`encode.c` 등 누락된 파일에도 우회 로직을 적용하여 모든 상황에서 행(hang) 현상을 방지합니다.

### 추천 수정 내용
- `encode.c`의 `th_set_user`, `th_set_group` 함수에서도 `getpwuid`, `getgrgid` 호출을 제거하고 파일 직접 읽기 방식을 적용합니다.

---

## 3. 메모리 제어 환경 변수 교정
오타를 수정하고, 개발 단계에서는 오류를 감지할 수 있도록 설정합니다.

### 추천 수정 내용 (`ecams_svr.c`)
```c
/* 수정 전 */
setenv("MALLOCK_CHECK_", "0", 1); 

/* 추천 수정 후 */
setenv("MALLOC_CHECK_", "1", 1); // 오타 수정 및 감지만 하고 실행은 계속 (Warning 출력)
```

---

## 4. Antigravity의 해결 접근 방식 요약
1.  **안정성 확보**: 행(Hang) 현상을 유발하는 시스템 함수 호출을 완벽하게 차단 (현재는 일부 누락됨).
2.  **무결성 유지**: 우회 로직 추가 시 발생한 신규 버그(NULL 참조 등)를 모두 제거하여 2차 크래시 방지.
3.  **진단 가능성**: 환경 변수 오타를 수정하여 최소한 메모리 문제가 발생하고 있다는 사실은 로그로 남기도록 함.

> [!TIP]
> 장기적으로는 `libtar` 라이브러리 내부에서 문자열을 복사하는 곳 중 고정된 크기(100자 등)를 넘어서 쓰는 곳이 없는지 전수 검사하는 것이 근본적인 해결책입니다.
