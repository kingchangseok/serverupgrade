## 1. 타입 정의 누락

### 증상
```
error: unknown type name 'socklen_t'
error: unknown type name 'uint64_t'
error: unknown type name 'dev_t'
error: unknown type name 'major_t'
error: unknown type name 'minor_t'
error: unknown type name 'nlink_t'
```

### 원인
오래된 UNIX 시스템에서 일부 타입이 표준 헤더에 정의되어 있지 않음

### 해결책 1: configure.ac 확인/수정
현재 configure.ac에 이미 포함되어 있어야 하는 타입 정의:
```autoconf
PSG_REPLACE_TYPE([socklen_t], [unsigned long], ...)
PSG_REPLACE_TYPE([uint64_t], [long long])
PSG_REPLACE_TYPE([dev_t], [unsigned long], ...)
PSG_REPLACE_TYPE([major_t], [unsigned int], ...)
PSG_REPLACE_TYPE([minor_t], [unsigned int], ...)
PSG_REPLACE_TYPE([nlink_t], [unsigned short])
```

**조치사항**: configure.ac에 위 매크로가 있는지 확인하고, 없으면 추가

### 해결책 2: 소스 코드 직접 수정
각 소스 파일(예: svrsrc/lanapi.c, svrsrc/util.c 등)에 추가:
```c
#include <config.h>

#ifndef socklen_t
typedef unsigned long socklen_t;
#endif

#ifndef uint64_t
typedef unsigned long long uint64_t;
#endif

#ifndef dev_t
typedef unsigned long dev_t;
#endif

#ifndef major_t
typedef unsigned int major_t;
#endif

#ifndef minor_t
typedef unsigned int minor_t;
#endif

#ifndef nlink_t
typedef unsigned short nlink_t;
#endif
```

## 2. 함수 선언 누락

### 증상
```
warning: implicit declaration of function 'select'
warning: implicit declaration of function 'socket'
warning: implicit declaration of function 'gethostbyname'
warning: implicit declaration of function 'inet_ntoa'
warning: implicit declaration of function 'bzero'
```

### 원인
함수 프로토타입이 포함된 헤더 파일 미포함

### 해결책 1: 소스 코드 헤더 추가
`svrsrc/lanapi.c` 및 네트워크 관련 파일 상단에 추가:
```c
#include <sys/types.h>
#include <sys/socket.h>
#include <sys/select.h>
#include <netinet/in.h>
#include <netdb.h>
#include <arpa/inet.h>
#include <strings.h>    /* bzero, bcopy */
```

### 해결책 2: configure.ac에 함수 체크 추가
```autoconf
AC_CHECK_FUNCS([select socket gethostbyname inet_ntoa bzero bcopy memset memcpy])

# 헤더 체크도 추가
AC_CHECK_HEADERS([sys/select.h strings.h])
```

**조치사항**: 
1. 모든 소스 파일에 필요한 헤더 추가
2. configure.ac에 AC_CHECK_FUNCS 추가

## 3. 중복 정의

### 증상
```
error: redefinition of 'struct sockaddr_in'
error: conflicting types for 'basename'
error: multiple definition of 'th_read'
```

### 원인
- 여러 헤더에서 동일 심볼 정의
- 시스템 라이브러리와 호환성 함수 충돌
- 같은 함수가 여러 .o 파일에 존재

### 해결책 1: 헤더 가드 강화
`inc/ecamsapi.h` 등의 헤더 파일 수정:
```c
#ifndef _ECAMSAPI_H_
#define _ECAMSAPI_H_

#ifndef _SOCKADDR_IN_DEFINED
#define _SOCKADDR_IN_DEFINED
// struct sockaddr_in 정의 (시스템 헤더와 충돌 방지)
#endif

#endif /* _ECAMSAPI_H_ */
```

### 해결책 2: basename 호환성 함수 조건부 컴파일
`tarcom/basename.c` 수정:
```c
#include <config.h>

// configure에서 시스템에 basename이 없을 때만 컴파일
#ifndef HAVE_BASENAME
char *basename(const char *path) {
    const char *ptr = strrchr(path, '/');
    return ptr ? (char *)(ptr + 1) : (char *)path;
}
#endif
```

configure.ac에 추가:
```autoconf
AC_CHECK_FUNCS([basename])
```

### 해결책 3: 중복 심볼 (th_read 등)
`tarsrc/internal.h` 수정:
```c
// 함수를 extern으로 선언만 하고 정의는 한 곳에서만
#ifndef TH_READ_DECLARED
#define TH_READ_DECLARED
extern int th_read(TAR *t);
#endif
```

**조치사항**:
1. basename 함수를 조건부 컴파일로 변경
2. 헤더 가드 강화
3. 중복 심볼 제거

## 4. Makefile 변수 미정의

### 증상
```
Makefile:5: *** missing separator.  Stop.
CC: command not found
make: cc: Command not found
```

### 원인
- `./configure` 실행하지 않아 Makefile.in이 Makefile로 변환되지 않음
- configure 실패로 변수 치환 안됨

### 해결책 1: configure 재생성
```bash
# autoconf가 없는 경우
$ autoconf   # configure.ac → configure
$ autoheader # config.h.in 생성

# configure 실행
$ ./configure
```

### 해결책 2: build_all.sh에 추가 체크 로직
현재 build_all.sh는 단순히 configure 실행만 하는데, 실패시 상세 안내 추가:
```bash
# configure 실행 후 Makefile 생성 확인
if [ ! -f Makefile ]; then
    log_fail "Makefile 생성 실패 - config.log를 확인하세요"
    log "일반적인 원인:"
    log "  1. 컴파일러 미설치 (CC 변수 확인)"
    log "  2. 권한 문제"
    log "  3. configure.ac 오류"
    exit 1
fi

# Makefile에서 중요 변수 확인
if grep -q "@CC@" Makefile; then
    log_fail "Makefile에 미치환 변수 존재 (@CC@)"
    log "  → ./configure가 제대로 실행되지 않음"
    exit 1
fi
```

**조치사항**: build_all.sh에 Makefile 검증 로직 추가

## 5. Solaris statvfs 문제

### 증상
```
error: 'struct statfs' has no member named 'f_bavail'
error: storage size of 'st' isn't known
```

### 원인
Solaris는 `statvfs`를 사용하지만 Linux는 `statfs`를 사용

### 해결책: 소스 코드 조건부 컴파일
`svrsrc/util.c` 등의 파일시스템 정보 조회 코드 수정:
```c
#ifdef __sun  /* Solaris */
#include <sys/statvfs.h>

int get_disk_space(const char *path) {
    struct statvfs st;
    if (statvfs(path, &st) != 0) {
        return -1;
    }
    return (int)(st.f_bavail * st.f_frsize / 1024);  // KB 단위
}

#else  /* Linux, AIX, HP-UX */
#include <sys/vfs.h>

int get_disk_space(const char *path) {
    struct statfs st;
    if (statfs(path, &st) != 0) {
        return -1;
    }
    return (int)(st.f_bavail * st.f_bsize / 1024);
}
#endif
```

configure.ac에 추가:
```autoconf
AC_CHECK_HEADERS([sys/statvfs.h sys/vfs.h])
AC_CHECK_FUNCS([statvfs statfs])
```

**조치사항**: 파일시스템 조회 코드를 OS별로 분기 처리

## 6. Alpine Linux (musl libc) 문제

### 증상
```
error: unknown type name 'u_char'
error: unknown type name 'u_short'
error: unknown type name 'u_int'
error: unknown type name 'u_long'
```

### 원인
musl libc는 BSD 타입(`u_char` 등)을 기본 제공하지 않음

### 해결책: 타입 정의 추가
`inc/ecamsapi.h` 또는 공통 헤더 상단에 추가:
```c
#include <sys/types.h>

/* BSD 타입 호환성 */
#ifndef u_char
typedef unsigned char u_char;
typedef unsigned short u_short;
typedef unsigned int u_int;
typedef unsigned long u_long;
#endif
```

또는 configure.ac에서 체크:
```autoconf
AC_CHECK_TYPES([u_char, u_short, u_int, u_long], [], [], [[
#include <sys/types.h>
]])
```

**조치사항**: BSD 타입 정의 추가 (Alpine/musl 대응)

## 8. Warning 해결

### 8.1 사용되지 않는 변수

#### Warning
```
warning: unused variable 'ret'
warning: unused parameter 'envp'
```

#### 해결책
```c
// 방법 1: 실제로 사용
int ret = some_function();
if (ret < 0) {
    fprintf(stderr, "Error: %d\n", ret);
    return -1;
}

// 방법 2: 명시적 무시
int main(int argc, char *argv[], char *envp[]) {
    (void)envp;  // 사용하지 않음을 명시
    // ...
}

// 방법 3: 컴파일 플래그 (Makefile)
CFLAGS += -Wno-unused-variable -Wno-unused-parameter
```

**조치사항**: 사용되지 않는 변수 제거 또는 (void) 캐스팅

---

### 8.2 형변환 경고

#### Warning
```
warning: cast from pointer to integer of different size
warning: assignment makes pointer from integer without a cast
```

#### 해결책
```c
// 잘못된 코드
int fd = (int)some_pointer;
void *ptr = (void *)some_int;

// 올바른 코드
#include <stdint.h>
int fd = (int)(intptr_t)some_pointer;
void *ptr = (void *)(uintptr_t)some_int;

// 또는 configure.ac에서
AC_TYPE_INTPTR_T
AC_TYPE_UINTPTR_T
```

**조치사항**: intptr_t/uintptr_t 사용

### 8.3 함수 프로토타입 불일치

#### Warning
```

```

#### 해결책
헤더 파일과 구현 파일에서 프로토타입 일치시키기:

```c
// inc/ecamsapi.h
char *Get_String_Time(void);

// svrsrc/util.c
char *Get_String_Time(void) {  // void 명시
    static char timebuf[32];
    // 구현
    return timebuf;
}
```

**조치사항**: 모든 함수 선언과 정의 프로토타입 일치 확인

### 8.4 Deprecated 함수

#### Warning
```
warning: 'bcopy' is deprecated: use 'memcpy' instead
warning: 'bzero' is deprecated: use 'memset' instead
```

#### 해결책: 전역 치환
```bash
# 소스 코드에서 일괄 변경
# bzero(buf, size) → memset(buf, 0, size)
# bcopy(src, dst, len) → memcpy(dst, src, len)
```

치환 스크립트:
```bash
#!/bin/bash
# replace_deprecated.sh

find . -name "*.c" -o -name "*.h" | while read file; do
    # bzero 치환
    sed -i 's/bzero(\([^,]*\),\s*\([^)]*\))/memset(\1, 0, \2)/g' "$file"
    
    # bcopy 치환 (인자 순서 주의!)
    sed -i 's/bcopy(\([^,]*\),\s*\([^,]*\),\s*\([^)]*\))/memcpy(\2, \1, \3)/g' "$file"
done
```

**조치사항**: bzero/bcopy를 memset/memcpy로 전역 치환

### 8.5 Format String 경고

#### Warning
```
warning: format '%d' expects argument of type 'int', but argument 2 has type 'size_t'
warning: format '%d' expects argument of type 'int', but argument 2 has type 'off_t'
```

#### 해결책
```c
// 잘못된 코드
size_t size = 1024;
printf("Size: %d\n", size);

off_t offset = 4096;
printf("Offset: %d\n", offset);

// 올바른 코드
size_t size = 1024;
printf("Size: %zu\n", size);  // size_t는 %zu

off_t offset = 4096;
printf("Offset: %lld\n", (long long)offset);  // off_t는 명시적 캐스팅

// time_t의 경우
time_t t = time(NULL);
printf("Time: %ld\n", (long)t);
```

**조치사항**: printf 포맷 스트링을 타입에 맞게 수정
